## Confirmed findings and implemented changes

### A01 — Registration ownership ignored the installation root

**Severity: high for local configuration integrity.** `register` treated equality with the current executable as sufficient ownership. An existing entry using that same executable with `--root OTHER_INSTALLATION bridge` was overwritten. This silently changed which local configuration/session an MCP host would use.

`src/register.rs` now checks transport type, command identity and the complete supported argument shape together. A project-installed binary with `bridge`, or an explicitly root-bound native command with the same canonical root, is recognized. An exact retired TypeScript entry remains migratable even after `src/bridge.ts` has been removed, but an arbitrary interpreter, foreign root, unrelated command or malformed argument array is not accepted.

Tests cover the foreign-root reproduction, other commands and transports, current-root idempotence, installed binaries, retired legacy paths and preservation of other servers/settings. The baseline binary reproduced the overwrite; the initial Rust test failed before the fix.

### A02 — Valid JSON with invalid root types caused panics

**Severity: medium.** An array, boolean, number or string in `.mcp.json` or `.claude/settings.local.json` reached `serde_json::Value` mutable indexing and panicked. `null` could also be silently converted to a new object, masking a malformed existing configuration.

The registration reader now distinguishes a missing file from a present non-object JSON value. It validates object roots and nested container shapes before mutation, returns a fixed safe diagnostic and leaves existing bytes unchanged. Tests use `catch_unwind` and byte comparisons across both destinations, including `null`, arrays, booleans, numbers, strings and malformed nested shapes.

### A03 — Registration followed linked destinations and could partially publish

**Severity: high for local state integrity; not a claim of remote exploitation.** A linked `.claude` directory directed writes outside the selected project. When its target rejected the settings write, `.mcp.json` had already been replaced.

Registration now rejects linked/reparse destinations and wrong file/directory types before writing; takes cooperative locks in a consistent order before reading; checks snapshots again; publishes the direct-endpoint denial before publishing MCP; and rolls back the exact original settings bytes on a handled second-publication failure. Rollback refuses to overwrite an intervening settings edit.

Unix tests exercise a linked settings directory and linked destination files. A Windows-only junction test exercises the reparse-point path without requiring symlink privilege. Unit tests inject a second-publication failure, covering exact-byte restoration, restoration of absence and preservation of a concurrent edit. Another test holds a live writer lock and verifies that neither destination is partially published.

**Boundary:** these are two separate atomic file replacements, not a crash-atomic multi-file database transaction. A crash between them can leave the denial installed without the new MCP entry; an idempotent retry completes registration. The change does not claim protection against an adversarial local process that can continually rename ancestors between filesystem calls. Protect the installation and state directories with the documented permissions/ACL procedure.

### A04 — Inactive proxy edits disconnected a healthy active route

**Severity: medium.** `Route` compared serialization of the entire `Connections` value. Importing an unused profile, editing a display label or modifying an unselected proxy changed that serialization and disconnected an otherwise unchanged connection, contradicting the import command's “active route unchanged” behavior.

The route snapshot is now a private effective identity: explicit direct mode, or selected proxy identifier plus normalized endpoint and credentials. The complete configuration is still validated, but irrelevant valid edits do not revoke the active route. SOCKS remote-DNS normalization remains intact. No `Debug` implementation exposes credential-bearing identity values.

Tests prove that direct-mode imports and selected-profile label/unselected-profile edits remain connected, while a selected endpoint change still fails closed.

### A05 — An observed invalidation could be undone on an old client

**Severity: medium.** An old `Route` could pass validation again after the original configuration was restored, even after its earlier check had observed a blocked/changed route.

A shared atomic revocation latch now permanently invalidates that route and every clone once a check observes a mismatch, missing/invalid configuration or blocking. A new route must be constructed for an explicit reconnect. The regression blocks, observes rejection, restores the old configuration, verifies all old handles stay rejected, and verifies a new handle works.

**Boundary:** the watcher polls at 100 ms; changes that occur and are reversed entirely between observations are not represented as durable events. This patch does not introduce a configuration event journal or claim instantaneous revocation.

### A06 — Output backpressure prevented the bridge from processing Block

**Severity: high for the fail-closed runtime contract.** The route-change branch sat in an inner `select!`, but `output.write_all` and `flush` were awaited inside a selected branch body. Once stdout stopped draining, that loop could no longer poll the route watcher.

A shared `Route::guard` now covers the complete relay future, including its nested writes and flushes, and cancels it on route invalidation. In-flight send futures are dropped and existing SDK cleanup remains bounded to two seconds. The cancelled stream is not resumed or replayed: a partial terminal write is possible on shutdown, so a host must reconnect rather than reuse that session.

Two deterministic tests wait until a custom writer reaches a permanently pending write or flush, then block/delete configuration. They require the relay to exit within three seconds, including the documented two-second cleanup allowance. The corrected local run exited at approximately 2.10 seconds; the baseline still exceeded the same three-second deadline. No increased retry count or ignored test conceals the original failure.

### A07 — OAuth cancellation stopped watching after response headers

**Severity: high for the same runtime contract.** `OAuthRoute::execute` selected between route change and `client.execute`, then read the body outside that guard. A server could send headers and stall its body while a Block/route change failed to cancel the operation promptly.

The shared guard now wraps request conversion/execution and the entire bounded response-body collection, preserving redirect policy and the 1 MiB maximum. The size check uses remaining capacity rather than unchecked addition. A loopback HTTP fixture sends a partial body, then blocks; changing the route must terminate metadata discovery within one second. This test failed on baseline and passes with the implementation.

`McpRoute` uses the same guard for request establishment. The enclosing relay guard covers subsequently consumed SSE streams; no independent promise is made that an arbitrary caller of the public request client receives a self-revoking raw stream outside the relay.

### A08 — Process termination left permanent sentinel locks

**Severity: medium.** Locks used `create_new` and removed a sentinel in `Drop`. Abrupt termination skips destructors, leaving future configuration writes and credential refreshes permanently “busy.”

`storage::Lock` now uses an operating-system exclusive file lock on a persistent private lock file. Normal guard destruction explicitly unlocks before closing the file; the OS also reclaims the lock after abrupt termination once all inherited handles have closed. The inode is deliberately not unlinked, so different waiters cannot accidentally lock different files. Invalid/linked lock files are refused and lock-contention remains a controlled error. Newly persistent root/config lock paths are ignored by Git.

A pre-handoff four-thread stability run exposed inherited-descriptor retention in the first OS-lock implementation. A deterministic duplicated-handle test reproduced the defect: closing only the parent guard left the same open file description locked. Explicit `unlock` in `Drop` fixes this without deleting the inode or retrying contention; the test also verifies that later closure of the inherited handle cannot unlock a replacement owner. This correction is included in the same PR before integration.

A subprocess acquires a lock and exits without destructors; the parent must reacquire it. Other tests verify a live owner stays exclusive, repeated releases/reacquisitions succeed and Unix linked lock targets are untouched.

**Upgrade requirement:** stop every old connector/menu/bridge process before replacing the executable and running this version. Do not mix the old sentinel-lock implementation and the new OS-lock implementation against the same state directory. Do not delete a persistent lock file merely because it exists. The migration does not clear credentials or authentication state.

### A09 — Truncated stdio input was silently treated as success

**Severity: medium.** EOF with a partial JSON frame but no newline returned `0`, and the relay reported a normal exit without delivering or rejecting the buffered message.

`read_bounded` now distinguishes clean EOF from an unterminated frame and returns a fixed error for the latter. Its size bound and incremental buffering remain. The regression sends a non-newline-terminated frame and verifies that the session does not report success.

## Verification evidence and CI

Baseline's 32 pre-existing Linux tests passed. With the first adversarial registration suite, 3 additional tests failed. The final-deadline boundary rerun used unchanged baseline implementation and confirmed 11 failures across registration/runtime/crash-lock cases; controls passed. These are runtime reproductions, not findings inferred solely from lint output.

The corrected local checkout passed all 55 Linux tests, formatting and strict Clippy with the exact locked dependencies. The Windows junction test is conditional and must be checked on the Windows CI job. See the PR checks for the final published commit's Windows x64, Linux x64, macOS arm64 and macOS x64 results, dependency audit, CodeQL and packaging evidence. Local Linux success is not a substitute for those platform results.

CI keeps the existing four-platform matrix, bounded nextest execution, two workers, zero retries, strict Clippy, packaging/launcher/cleanup checks, dependency audit, dependency review and CodeQL. This PR adds bounded JUnit metadata and always-attempted evidence upload. JUnit does not store test stdout/stderr, and the artifact allowlist contains only the JUnit report and verification metadata, not state, token files, private logs or entire scratch directories. Missing reports on a failure before tests are reported as missing, not invented.

Dependabot already covers Cargo and GitHub Actions daily. PR #1 was already closed, not merged, before this audit. A major/minor-breaking SSE dependency migration must be evaluated against the pinned rmcp version and full network suite rather than forced by a blind version bump. No dependency bump is necessary for these implemented fixes.

## Optional improvements for independent evaluation

These are proposals, not additional confirmed defects or hidden unfinished repairs: bounded asynchronous waiting for refresh-lock contention; a durable route-change generation/event record if sub-poll changes must invalidate clients; fault-injection/fuzzing for callback and proxy parsing; OS credential-store integration beyond file ACLs; typed log levels and consistent fixed-message error-path logging; and bounded reads before loading large local import files. Select improvements only after checking the actual Rules, measured need, compatibility and tests. Do not expand scope into live account automation or a new transport without an approved requirement.

## Independent integration review

The reviewed starting head was `fddfe211c2cfc13e94ebae9c4381cb9d6d33987d`. Its final hosted jobs completed:
Windows 50 tests and Linux/macOS 55 each, with zero failures or skips; JUnit and bounded-run receipts
were inspected independently. Dependency Review still failed before comparison because Dependency Graph
was unavailable. Integration was blocked at that historical point pending the prerequisite and final-head checks; the later disposition index records its resolution.

The review added a regression for a concurrent settings edit with equivalent JSON but different bytes.
Rollback must compare exact publication bytes, not parsed value equality, to preserve that edit. Framing
coverage now directly checks the expected truncated-input diagnostic and complete-frame/clean-EOF success;
the earlier relay test using a closed endpoint could fail for an unrelated transport reason. Child lock
and Windows junction fixtures are hidden, bounded and reaped. The OAuth stalled-body fixture observes a
pending operation instead of a blind sleep. These changes require new final-head CI evidence; earlier
results are not carried forward as proof of the changed tree.

The compatible serde_json patch moves from 1.0.152 to 1.0.154; no transport SDK migration is required.
At that baseline, optional refresh waiting, durable route journaling, fuzz infrastructure, OS credential
storage, typed logging and import size policy were deferred. Subsequent narrower refresh waiting,
effective-route revisions, import bounds and typed diagnostics superseded parts of that statement; see
[current dispositions](README.md). General fuzz infrastructure and OS credential-store migration remain
unadopted proposals. Original fixed-message logging, route checks and protected storage were retained.
